# Deployment charts

Helm charts and the Argo CD bootstrap manifests for every brand. Charts live here;
each brand's values live in the application repository that builds the image, so a
CD run updates a tag with its own `GITHUB_TOKEN` and no cross-repo credential.

## Charts

Charts are brand-neutral. A brand is a values file, not a chart.

- `charts/marketplace/` — API, worker, migration Job, PostgreSQL, storage PVC,
  nightly backup and the API route.
- `charts/storefront/` — the Next.js storefront and its route.
- `charts/agent/` — the AI agents and their PostgreSQL.
- `charts/motiv-agent/` — Motiv's standalone chatbot. Still separate; folding it
  into `charts/agent` is open work.
- `charts/crm/` — standalone CRM API, panel, migration hook and shared-host route.

Only `venu`, `venu-frontend`, `agents`, `motiv-agent` and `crm` have a file under
`argocd/`. The three `venu-market*` Applications are generated by `venu`'s
`brandApplications` block and are owned by Argo — do not apply them by hand.

The platform owner bootstraps CRM once with `argocd/crm.yaml`. Before applying it,
create the `venu-crm` namespace Secrets and DNS prerequisites listed below; Argo
then owns all CRM resources.

The `argocd/` directory is not watched by a root Application in this repository.
Adding this file alone does not create CRM: an authorized platform owner must
register the bootstrap Application once after release and prerequisite review.
CRM is not a `brandApplications` child. No live bootstrap is performed by local checks.

### CRM external prerequisites

- `venu-crm/venu-market-registry`: registry credentials for both private images.
- `venu-crm/crm-env`: all runtime `CRM_*` values used by both `crm-api` and
  `/crm-migrate`, including the production PostgreSQL DSN and S3 endpoint,
  bucket, region and credentials. Secret values stay out of Git.
- `crm.venu.uz`: DNS record pointing at the shared Gateway's public address, with
  TLS terminated by the external proxy/CDN (the current Gateway exposes HTTP) or
  by a future HTTPS listener covering this hostname.
- The Gateway dataplane source namespace must equal
  `networkPolicy.gatewayNamespace` (default `default`), and PostgreSQL must be
  reachable on TCP 5432 while S3 is reachable over HTTPS 443.
- Set `CRM_ENV=production`, `CRM_PUBLIC_BASE_URL=https://crm.venu.uz`,
  `CRM_HTTP_ADDR=:8091`, `CRM_STORAGE_DRIVER=s3`,
  `CRM_DATABASE_URL`, `CRM_STORAGE_ENDPOINT`, `CRM_STORAGE_REGION`,
  `CRM_STORAGE_BUCKET`, `CRM_STORAGE_ACCESS_KEY` and `CRM_STORAGE_SECRET_KEY`
  in `crm-env`. Provision the bootstrap administrator securely (password at
  least 12 characters); plan credential rotation, database backup and rollback.
  `postgres.*`, `storage.*`, `migration.image` and `migration.secretName` in the
  supplied backend values are not consumed: API and migration share `api.image`
  and `api.secretName`; no database or storage Secret is created by this chart.
- Migration is a `PreSync` hook, before workloads and chart network policies.
  Pre-create the namespace and Secrets; migration must reach PostgreSQL under
  any existing namespace policies. Use full syncs: selective resource sync skips
  hooks. Migrations must remain compatible with the old API during rolling updates.
- The Gateway listener must allow routes from `venu-crm`; the Gateway object's
  namespace does not prove its dataplane namespace. Verify the CNI supports the
  rendered namespace selectors (existing marketplace policy records limitations).
  Add trusted worker namespaces through `networkPolicy.ingestionNamespaces`;
  network permission does not replace ingestion-token authentication. API egress
  allows DNS in `kube-system` and TCP 5432/443 to any destination, not endpoint
  allowlisting; custom DB/S3 ports or DNS topology require policy adjustments.
- Use a dedicated private storage origin, exact-origin browser PUT CORS, and a
  staging-prefix lifecycle. Signed PUT requires the exact reserved byte length
  and MIME type; completion publishes an immutable final object. Do not reuse
  application cookies or host application pages on the storage origin.
- Backend CD must replace both `api.image.tag` and `panel.image.tag` in
  `helm/crm-values.yaml` with immutable commit SHAs before production sync.
- The panel image must run as UID/GID 101, permit that user to read its static
  files, and support binding port 80 with only `NET_BIND_SERVICE`; it must not
  depend on root-time nginx filesystem rewrites. The chart bypasses the image's
  entrypoint, mounts its own nginx configuration and uses writable `/tmp` with
  a read-only root filesystem.

Names still to fix: the `venu` namespace runs **Latta Putta**, and `venu-market`
runs **Venu**. The namespaces are historical and renaming them means moving a
production database, so it is deliberately separate work.

## Local checks

```bash
helm lint charts/marketplace -f ../backend/helm/lattaputta-values.yaml
helm lint charts/agent       -f ../agent/helm/lattaputta-values.yaml
helm lint charts/storefront  -f ../venu-market-frontend/helm/venu-values.yaml
helm lint charts/crm         -f ../backend/helm/crm-values.yaml

helm template venu        charts/marketplace -f ../backend/helm/lattaputta-values.yaml >/dev/null
helm template venu-market charts/marketplace -f ../backend/helm/venu-values.yaml       >/dev/null
helm template agents      charts/agent       -f ../agent/helm/lattaputta-values.yaml   >/dev/null
helm template crm         charts/crm         -f ../backend/helm/crm-values.yaml \
  --set route.hostname=crm.venu.uz >/dev/null
```

Before changing a chart, render it with every brand's values and diff against the
render from before the change. A chart is shared: a change made for one brand
lands on all of them.

This repository is public because it holds no secret values — only Secret names.
The private values repositories are read through an Argo CD repository credential.

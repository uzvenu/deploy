# Image-service seccomp GitOps

Codex remains pinned to 0.160.0. Chart defaults disable both the service and
`seccomp.enabled`; only `agent/helm/lattaputta-image-service-values.yaml` opts in.
The Latta Putta root Application remains manual-sync pending parent security
review, credentials and an immutable service image tag. No Venu bootstrap.

## Single source and updates

Canonical policy: `agent/services/image-service/seccomp-amd64.json`, generated
by its `build-seccomp.py`. Its Moby Apache-2.0 license is packaged alongside it.
From deploy, run:

```
python3 tests/image-service-profile.py --sync
python3 tests/image-service-profile.py
ruby tests/image-service.rb
```

Commit source updates and generated chart assets together after review. The test
requires sibling agent sources, compares exact bytes and license, and runs the
canonical default-deny/bounded-extension tests. ConfigMap data is generated by
Helm directly from those bytes; its immutable name and Localhost filename derive
from SHA-256. Never hand-edit the chart copy.

## Node security and rollout

The minimal DaemonSet runs only on Linux amd64 nodes, matching the workload.
Its root init container uses RuntimeDefault, drops ALL capabilities, forbids
privilege escalation, has read-only rootfs and no API token. Its only writable
mount is `/var/lib/kubelet/seccomp/codex-image-service` (DirectoryOrCreate).
Root is necessary to create root-owned profile files; neither privileged mode
nor SYS_ADMIN is needed. The nonroot idle container has no volume mounts.

Installation checks the source hash, accepts only an identical regular existing
file (not a symlink), or copies to a same-directory temporary file, chmods 0644
and atomically publishes with a no-clobber hard link. Conflicting content fails
closed. Other profiles are never overwritten or deleted. Old hashed versions
remain for rollback; garbage collection is a separately reviewed operation.

The service has no host mounts and uses `Localhost` with
`codex-image-service/<full-sha256>.json`. Policy allows bounded user-namespace
creation and mount/pivot_root/umount2 for bubblewrap, increasing kernel attack
surface over RuntimeDefault; service UID 1000 retains zero capabilities.
Nodes must support this tested policy (native amd64, kernel >=6.8, unprivileged
user namespaces and compatible LSM rules). Review node policy admission allowing
this narrowly scoped root/hostPath installer before sync. No live changes are
performed by these scripts. GitOps installation may race service startup: missing
profiles fail container creation until the installer completes; never fall back
to Unconfined. Review installer completion on every eligible node before traffic.

## Credentials and activation prerequisites

In namespace `agent`, provision out-of-band `codex-image-service-auth` with
`auth.json`, `codex-image-service-env` with required `IMAGE_SERVICE_TOKEN` and
optional `IMAGE_SERVICE_MODEL`, and pull secret `venu-registry`. Configure the
same bearer token in the Latta Putta backend API/worker. Never store these values
in Git or print them. Health and credential-free sandbox smoke do not prove
account authentication/quota; actual generation has provider cost/data sharing.
Dedicated agent CI uses the canonical local seccomp path for Docker smoke before
publishing and bumping the immutable image tag. Parent review is required before
commit/push; deployment is GitOps only.
